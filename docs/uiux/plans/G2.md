# G2 plan: theme and app chrome (palette, QSS, tabs, menus, dialogs)

Status: plan only, nothing implemented. Paths are relative to the repo root.
Context: the user will run the chair test (tests/chair/chair.fcs) in the GUI and screen-record it once the fixes land, so the
chrome has to look right during a scripted run, and the script and non-interactive paths must behave exactly as they do now.

## UX-13 (critical) Light text on light; black checkboxes, combo popups, tables, file dialog
- Root cause: src/app/main.cpp:136-137 sets the Fusion style and the QSS but no QPalette, so the qt6ct dark palette
  (noctalia.conf) is used for WindowText/Text/Base/Button/ButtonText/Highlight. resources/theme-light.qss:30-34 sets
  `QMenu::item:disabled` but no enabled colour on QMenu/QMenu::item, which is why enabled and disabled look swapped. :62 styles
  inputs without `color:`. Nothing covers QCheckBox::indicator, QComboBox QAbstractItemView, QTableView/QTreeView/QHeaderView,
  QTabBar, QScrollBar, QPlainTextEdit (#CommandHistory) or QToolTip font. The GTK save dialog (MainWindow.cpp:1124/1208 plus
  dialogs in PartTools, AssemblyModule, ExportStlTool, DrawingTools) follows adw-gtk3-dark.
- Fix:
  - Add src/app/Theme.{h,cpp} with `applyLightTheme(QApplication&)`: Fusion style, a full light QPalette for every role in
    Active/Inactive/Disabled (Window #F2F3F5, Base #FFFFFF, AlternateBase #F7F7F8, Text/WindowText/ButtonText #2B2E33,
    Button #FFFFFF, Highlight #0696D7, HighlightedText #FFFFFF, ToolTipBase #FFFFFF, ToolTipText #2B2E33, PlaceholderText #8A9099,
    Link #0696D7; Disabled text #A9AEB5), then the QSS, then `QToolTip::setPalette`. The existing GLOB_RECURSE in
    src/app/CMakeLists.txt picks the new file up, so no CMake change is needed. main.cpp calls it in place of lines 136-137.
  - main.cpp, before `QApplication app`: `QCoreApplication::setAttribute(Qt::AA_DontUseNativeDialogs)`. This one global line
    switches every QFileDialog/QColorDialog to the Qt widget dialog, which then uses our palette, without touching G4's files.
    Alternative if the native dialog is wanted: leave it and accept the GTK theme.
  - Optional: `app.setFont()` with a fixed sans family and 9pt so qt6ct's font does not leak in (also helps the serif tooltip in
    SOLID-7 and the large tooltip in SKETCH-18).
  - Complete theme-light.qss: `QWidget{color:#2B2E33}` as the base; `QMenu{color}` and `QMenu::item{color:#2B2E33}`, then
    `:selected`, then `:disabled` last (order matters); `QMenu::section` / separator-with-text; inputs `color` plus
    `:disabled` and `selection-color`; QComboBox drop-down and `QComboBox QAbstractItemView{background:#FFF;color;selection-*}`;
    `QCheckBox::indicator`/`QRadioButton::indicator` (unchecked white with a #8A9099 border, checked #0696D7 with a check SVG,
    disabled); QTableView/QTreeView/QListView with `gridline-color`, and QHeaderView::section; QTabBar (see UX-14); QScrollBar
    (light groove and handle); QPlainTextEdit/QTextEdit; `QToolTip{font-size:9pt;}` (SKETCH-18); QSpinBox buttons; QGroupBox;
    QProgressBar.
  - Add icons/check.svg (and maybe radio-dot) to resources/icons plus fabricad.qrc for the indicator image. Use only colours
    from the test_icons.cpp palette.
- Possible effects and how to avoid them:
  - Tests and e2e build MainWindow without main.cpp, so they keep the platform palette. Calling `applyLightTheme` from
    test_main_window.cpp is optional; no test asserts on colours. Offscreen/headless runs are unaffected because QSS works
    without a display.
  - The QSS `QWidget{color}` base can override colours that G3/G4 widgets set inline (16 setStyleSheet calls in src). Inline
    sheets have higher precedence on their own widget, so nothing breaks. G3/G4 must not add per-widget colours; check
    PropertyPanel, FeatureValueBox and the drawing sheet after the change.
  - The viewer overlay labels (ViewCube text, manipulator tooltip) are painted by OCCT/G1 and do not use the palette. Only
    Qt-widget overlays change.
  - A Highlight change can tint browser selection. The QSS already sets the Browser item colours, so it stays consistent.
  - A non-native file dialog loses GTK bookmarks/portal integration. This is acceptable on this desktop; mention it in the
    README.
  - Badge icons (Icons.cpp:28) hard-code their colours, so they are unaffected.

## UX-14 (medium) Document tabs black; ribbon tab strip scroll arrows black; SOLID clipped
- Root cause: the QSS rule `#DocumentTab` (theme-light.qss:10) does not match the tab bar's object name `DocumentTabs`
  (MainWindow.cpp:237), so the document tabs get no style and fall back to the dark palette. The ribbon tab bar
  (Ribbon.cpp:56-61) sets `font-weight:600; font-size:8pt` on the `::tab` sub-control only. QTabBar measures size hints with the
  widget font, so the bold text is wider than the measured tab: SOLID is clipped and the scroller QToolButtons (dark) appear.
  The tab bar is also added with AlignLeft, so it keeps an old sizeHint after the SKETCH contextual tab is inserted.
- Fix: rename the selector to `#DocumentTabs QTabBar::tab` / `QTabBar#DocumentTabs::tab` with normal, :selected (white
  background, 2px #0696D7 top or bottom border, bold), :hover and close-button (`::close-button` image app-close.svg) states,
  plus `QTabBar QToolButton{background:#F7F7F8;border:none}` and `QTabBar::tear{width:0}`. Ribbon: move the font onto the
  widget (`tabs_->setFont(bold 8pt)` or `#RibbonTabs QTabBar{font-weight:600;font-size:8pt}`), then
  `tabs_->setUsesScrollButtons(false)`, `setElideMode(Qt::ElideNone)`, and `tabs_->updateGeometry()` after inserting or
  removing the contextual tab.
- Effects: with scroll buttons off, a very narrow window grows the minimum width of the ribbon row. Use a minimum window
  width or keep scroll buttons only for the document tab bar. Ribbon::updateTabStyle may set per-tab colours, so check it
  does not fight the QSS. If the tab bar sizeHint grows, re-check the ribbon layout in DRAWING (longer tab list).

## UX-17 (medium) Command dialogs occlude the model/ViewCube and resize; Dimension hint clipped
- Root cause: CommandDialog.cpp:19-21,127 docks it at the top right (x = width - 300 - 12, y = 150, just under the ViewCube).
  `adjustSize()` in setMessage (:119) and reposition (:124) makes it grow or shrink when the message or body changes after
  the first pick. There is no height cap, so Joint is 510 px. The Dimension hint is a QLabel without wordWrap in G4's
  AnnotationTools.cpp:161, and a fixed-width form clips it.
- Fix (CommandDialog.cpp only):
  - Default position at the top left of the viewport, `QPoint(kLeftMargin=12, kTopMargin=12)`, since the viewport begins at
    the browser dock edge. Double-click the title to re-dock to the left (update the comment at :171).
  - Wrap bodyLayout_ content in a QScrollArea (frameless, no horizontal scroll) with
    `maximumHeight = min(viewport height - 24 - title - buttons, ~420)`, which caps Joint.
  - Stable size: record the height after `present()` (`minHeight_ = height()`); afterwards only grow
    (`setMinimumHeight(max)`) and never shrink until the next `present()`. Reserve one line for message_ (keep it in the
    layout with an empty text instead of hide/show, or `setMinimumHeight(fontMetrics().lineSpacing()*2)`).
  - In present(): for every `body->findChildren<QLabel*>()` whose text is longer than ~40 characters and that has no pixmap,
    call `setWordWrap(true)`. This fixes the Dimension hint without editing G4's file. If preferred, G4 can add
    `setWordWrap(true)` at AnnotationTools.cpp:161 instead.
- Effects:
  - SketchPalette::reposition(dialog_) (MainWindow.cpp:881, SketchPalette.cpp:165) assumes the dialog is on the right. Update
    it together (see UX-18), or the palette may jump left onto the dialog.
  - A left dock may cover the model if the browser is hidden. Clamping in reposition already keeps it inside the viewport.
  - G1's ViewCube is uncovered, which is good. Fit/framing margins (G1 VIEWER-9) should reserve the left 312 px rather than
    the right while a dialog is open. Tell G1, and do not edit viewer code here.
  - test_main_window.cpp:174-313 checks only visibility, the body and the OK state, not geometry, so it stays green. The
    QScrollArea changes the parent of the body. `body()` must still return the original widget and
    `findChild<QLineEdit*>("dialogField")` on it still works. dismiss() has to remove the body from the scroll area (keep the
    deleteLater rule).
  - Drawing tabs (DocumentTab.cpp:47) host the dialog over the sheet. Top left there covers the sheet's title-block corner
    less than before, which is fine.

## UX-15 (low) Hole promoted icon looks like Box
- Root cause: part.hole resolves to resources/icons/part-hole.svg (Icons.cpp:116). That SVG is part-box.svg with a small
  3.6x1.8 ellipse, which cannot be told apart at 16-24 px. feature-hole.svg is identical.
- Fix: redraw part-hole.svg and feature-hole.svg as a plate (flat slab) with a large, dark through-hole (outer ellipse r~6,
  #3C4148 fill, inner wall arcs, an orange #E8811A axis/center mark), using only the test_icons.cpp palette colours. No mapping
  change is needed, because the id-to-file lookup already works.
- Effects: test_icons.cpp validates colours and the viewBox, so run it. The browser feature icon changes too, which is intended.

## UX-16 (low) Nav menus: blank first row in settings; "Home Home" in Views
- Root cause: NavBar.cpp:179 (`addSection` as the first item) is drawn by QStyleSheetStyle as a bare separator, because the QSS
  styles `QMenu::separator` and drops section text, so the row looks blank. The Display menu (:96) has the same problem.
  NavBar.cpp:165 `"Home\tHome"` repeats the label as the shortcut text.
- Fix: replace `addSection(text)` with a disabled, non-checkable header action in bold (or a QWidgetAction QLabel styled
  `#MenuHeader`), and do not start a menu with a separator. Change the Views entry to `"Home View\tHome"` (or
  `"Home"` + `setShortcut(Qt::Key_Home)` with `setShortcutVisibleInContextMenu`).
- Effects: NavBar::refresh (:213-226) and the nav menu's aboutToShow loop (:198-203) iterate `actions()` and use `data()`.
  Header actions must have no data and must not be checkable so the loops skip them, which matches the existing checks.
  Other menus that use addSection (marking menu, browser context menus in G4) would get the same fix only if they also show
  blanks. Use a shared helper `addMenuHeader(QMenu*, text)` in Icons.h or a small MenuUtil, which G4 can adopt later.

## UX-18 (low) Sketch palette covers geometry and cannot be moved
- Root cause: SketchPalette.cpp:24-26,165-178 places it at a fixed top right position (x = width - 230 - 12, y = 150 or

- Fix: give the title bar the same drag behaviour as CommandDialog (factor out a small `OverlayDragHelper` used by both),

- Effects: MainWindow.cpp:881 still calls `reposition(dialog_)`, so keep the signature. Sketch tools (G3) do not depend on
  the palette position. Collapsing must not hide the checkbox state the tools query, since the widgets keep their state.

## UX-19 (low) Help dialog misaligned, log popup overflows, first Enter swallowed
- Root cause: in MainWindow.cpp:1333-1365 the extra rows have no icon, so text starts at column x0 while tool rows are
  indented by the icon, and the "Command" column stretches while the others are not sized. CommandLine.cpp:110-111 moves the
  history pane to `edit_ top - 180` with no clamp, so it overflows the window or screen when the status bar is low or the
  edit is near the right edge (width 520). CommandLine.cpp:62-66: when the completer popup is visible (typing "app.help"
  matches), Enter is consumed by the popup or the guard returns, so the first Enter only closes the popup.
- Fix: help: set a blank 16x16 icon (or `setIconSize` with an empty QIcon pixmap) on the extra rows, use
  `setUniformRowHeights(true)` and `header()->setSectionResizeMode(ResizeToContents)` for columns 1 and 2, and give the
  dialog the themed palette (UX-13). History pane: clamp it to `window()->geometry()` (x such that the right edge is at most
  the window right edge, y at least the window top, height = min(180, available)), or parent it to the main window as a
  child overlay instead of a Qt::Tool window. Enter: in eventFilter, on Return/Enter, if the popup is visible and has no
  current index, hide it and `submit(edit_->text())`, otherwise take `popup()->currentIndex()` text and submit. Also connect
  `QCompleter::activated(QString)` to fill and submit.
- Effects: ScriptRunner may drive CommandLine::submit directly, so check it does not rely on returnPressed. The chair test
  and test_scripting must stay green. Submitting on completer activation could run a command the user only meant to
  complete. Submit only when the activation came from Enter (not a click or Tab).

## UX-20 (low) Status bar shows a stale body name after rename
- Root cause: MainWindow.cpp:739-742 updates selectionLabel_ only on `SelectionModel::changed`. A rename emits
  `Document::bodyChanged`/`featureChanged`/`componentChanged` (Document.h:207-217), which are not connected to
  updateSelectionStatus (:1009).
- Fix: in the per-tab hookup (~:733), connect bodyChanged, featureChanged and componentChanged with
  `whenActive([this]{ updateSelectionStatus(); })`, coalesced through the existing scheduleStateRefresh or a 0 ms single-shot so
  recompute storms do not reformat the label many times.
- Effects: bodyChanged fires on every recompute, and describeSelection is cheap, so coalescing removes the remaining cost.
  test_main_window.cpp:277 compares selectionText with the body name. Add a rename case there.
