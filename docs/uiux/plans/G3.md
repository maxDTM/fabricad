## UX-24 (high) Offset adds DOF but draws nothing — ROOT CAUSE CONFIRMED
- **Repro:** slot (0,0)-(40,0) with R10, offset 10 towards (0,20), which is outside. Result: four
  degenerate curves going inward: both lines on y=0 and both arcs with `r = 1e-6`. The status shows
  "+10 DOF" but nothing is visible. An inward offset (side (20,7)) works.
- **Root cause:** `Sketch.cpp:911-919` (`Sketch::offset`) decides the side from `run.front()` only,
  using that curve's infinite line or full circle. `orderChains` (`Sketch.cpp:834`) can put any
  curve first. For the slot it puts the bottom line first, and every point above y=-10, inside or
  outside the slot, counts as "inside". Next, `offsetCurve` (`Sketch.cpp:880-885`) clamps a negative
  radius to 1e-6 instead of failing, which hides the error.
- **Fix:**
  1. Decide the side using the run curve nearest to `side` (`distanceTo`), with that curve's own
     `reversed` flag. For a closed run, use an inside/outside test of the loop (winding number on
     `polylines()`), with the traversal sign (shoelace) choosing left or right.
  2. In `offsetCurve`, when an arc or circle radius would be ≤ ~1e-6, mark the result degenerate.
     `offset()` then returns empty for that run, and the tool already says "Offset produced no
     geometry".
- **Test:** slot offset outward and inward, by both a cursor side and a typed distance. Check the
  radii (r±d) and that the lines are at y=±(10±d). Also test a rectangle and an L-chain (open run)
  with the side next to the second segment.
- **Possible effects:** the rubber-band preview (`ModifyTools.cpp:412-422`) uses the same function,
  so it gets fixed too. Offsets of an open chain may flip side in cases that "worked by luck" before.
  The nearest-curve rule is the intuitive one, so this is acceptable. `test_sketch_ops` has offset
  tests; re-run them.

## UX-23 (high) Editing a dimension moves unrelated geometry
- **Root cause:** `SketchInference.cpp:183-188` (`applyInference`) commits tracking-line alignment
  (`alignedXWith`/`alignedYWith`) as point-to-point `Vertical`/`Horizontal` constraints with
  `internal = true`. `SketchSession.cpp:496` skips glyphs for internal constraints, so they are
  invisible. They tie separate shapes together.
- **Fix:** delete that block. Fusion only uses tracking lines to place the point and does not add
  constraints for them. Keep the snapped position (the `r.point` changes made in `infer`).
  Coincident, PointOnCurve, H/V, parallel, perpendicular and tangent inferences stay.
- **Test:** draw (or simulate through `applyInference`) a point aligned to another shape's corner.
  Assert that no constraint references both shapes, and that a dimension change on shape B leaves
  shape A's bbox unchanged.
- **Possible effects:**
  - DOF counts rise for sketches drawn with the mouse. Tests use typed or exact input
    (`inferExact` sets `allowAlignment=false`), so no test should change. `test_tools.cpp:104` counts
    exclude internal constraints anyway.
  - Documents saved earlier still contain the hidden constraints. Optional migration on load: drop
    `internal` H/V constraints whose two points belong to different, unconnected chains. Leave this
    out unless asked, because it changes old files silently.
  - The chair test is unaffected (typed input).

## UX-22 (critical) Sketch fillet on a dimensioned sketch over-constrains / destroys it
- **Status:** a headless typed repro (40x25 RECT plus a 60x30 line chain with typed dimensions,
  SFILLET 5 on a chain corner) **works** today: `retargetTrimmedDimensions` (`Sketch.cpp:1239`)
  already re-targets typed dimensions. The tester's sketch was drawn with the mouse, so it also had
  hidden alignment constraints (UX-23) and Dimension-tool dimensions.
- **Root cause:** `Sketch::fillet` (`Sketch.cpp:1137-1236`) only removes the Coincident between the
  two trimmed ends (`Sketch.cpp:1222-1225`). Every other point-level constraint on a moved end still
  pins the new tangent point to the old corner's relations. That includes the hidden UX-23 H/V
  alignments, Coincident or PointOnCurve with a third curve, Fix, Symmetric, Midpoint, polygon
  `PointOnCurve(vertex, circle)`, and `Equal` on the shortened lines. This gives conflicts or
  distortion. A second problem: `SketchSession::commitEdit` (`SketchSession.cpp:206-224`) commits
  even when the solve fails, which leaves a broken sketch. Possibly the solver also writes back
  diverged parameters, which would explain the "vanished" geometry with the labels still shown.
- **Fix:**
  1. **Virtual sharp:** before trimming, if any constraint other than the corner coincident and the
     dimensions already handled by `retargetTrimmedDimensions` references `{id, moved}`, add a
     construction `Point` at the old corner. Constrain it with `PointOnCurve` on both lines
     (internal; for a line/arc corner use `PointOnCurve` to the arc's circle). Then remap those
     constraints from the moved end to that point. The point is visible as a construction point,
     like SolidWorks' virtual sharp, so no hidden coupling remains. When nothing needs it, add no
     point; this keeps the chair and `test_fillet_dimensions` output unchanged.
  2. **`Equal` on a trimmed line:** this covers UX-27b (the polygon). Drop it, and if the line was in
     an equal-set with ≥ 2 untrimmed members, re-chain the remaining members' Equal constraints among
     themselves. With all polygon vertices on the circle (through the virtual sharp), the polygon
     stays regular. Report dropped constraints through the existing `takeDemotedDimensions` message
     path. Generalise it to "changed constraints".
  3. `FilletTool::apply` (`ModifyTools.cpp:160-174`): after `fillet()`, run `solve()`. If the result
     is Conflicting or Failed, `cancelEdit()` and show "Fillet would over-constrain the sketch
     (<constraint names>)" instead of committing.
  4. Check that `SketchSolver` keeps the previous parameters when it does not converge. If it does
     not, restore them in `Sketch::solve` on failure.
- **Tests** (extend `test_fillet_dimensions.cpp`):
  - (a) Line chain with H/V, a Dimension-tool `Distance` on the top line, and a point-to-point
    alignment to a separate fixed rectangle corner. Fillet the top-left corner: solve ok, rectangle
    unchanged, chain bbox unchanged.
  - (b) Inscribed hexagon or pentagon: fillet one corner, then the other vertices stay on the circle
    and the untrimmed sides stay equal.
  - (c) A fillet that cannot be solved is rolled back (geometry count unchanged).
  - The existing slab tests must still pass with no extra point.
- **Possible effects:**
  - Chamfer (`SketchTransform`/`chamfer`) shares the trim logic. Apply the same remap there, or
    leave chamfer explicitly untouched and add a TODO.
  - New construction points appear in `INFO sketch:` output and in the geometry counts of scripted
    tests. Only sketches with extra point constraints are affected, and the chair is not.
  - Rolling back on failure changes behaviour for users who relied on "commit then fix". This is
    acceptable and matches Fusion.

## UX-29 (medium) Line from the origin gets no coincident
- **Root cause:** the sketch origin is not sketch geometry. It is only drawn
  (`SketchSession.cpp:447-448`). `infer()` (`SketchInference.cpp:39-57`) only hits real points, so
  there is no snap and no constraint. The red marker the tester saw is always drawn.
- **Fix:**
  - Add `bool onOrigin` to `InferenceResult`. In step 1 of `infer`, if no sketch point is closer and
    `|cursor| <= tol`, snap to (0,0) with the Coincident glyph.
  - In `applyInference`, for `onOrigin` add a point `Fix` on `newPoint` (not internal). In
    `renderConstraints`, draw a point Fix whose position is (0,0) as the coincident dot instead of a
    lock, so the user can still select and delete it.
  - Also handle typed `0,0` through `inferExact` (tolerance 1e-6), as Fusion does.
  - Rejected alternative: a virtual origin GeoRef (geo id 0). It needs solver, `pointOf`, JSON and
    projection changes, which is too invasive for this round.
- **Test:** a line from the origin with H plus a typed length gives `dofs()==0`. A line from (5,5)
  gives no Fix.
- **Possible effects:** typed sketches with a vertex exactly at (0,0) lose 2 DOF. A user dimension
  from that point to the origin would then be redundant, and the Dimension tool would offer
  "driven", which is correct. Check `bracket.fcs` (it starts at `0,0`): its `CHECK`s use volumes and
  parameters, not dof, but re-run it. The chair rectangles do not touch the origin. Two
  `onOrigin` Fixes on one point cannot happen (onPoint wins).

## UX-25 (medium) Dimension value editing: no editor on creation, field not focused, Enter ignored
- **Root cause:** the Value phase already exists. `DimensionTool::place` (`ModifyTools.cpp:1025-1072`)
  calls `refreshToolDialog`, and `createDialog` (`ModifyTools.cpp:876-890`) builds a `QLineEdit` and
  calls `selectAll()`. It never calls `setFocus()`, and the same is true of `DimensionEditTool`
  (`ModifyTools.cpp:1170-1184`). Keys therefore go to the viewer. Enter reaches
  `ToolManager::accept`, where `edit_->isModified()` is false, so the tool finishes with the old
  value: "Enter ignored". The editor also sits in the right-hand command dialog, far from the label,
  so the tester did not notice it (the repaint lag of UX-01 made this worse).
- **Fix:**
  - In both `createDialog`s, after creating the edit, call
    `QTimer::singleShot(0, edit, [edit]{ edit->setFocus(Qt::OtherFocusReason); edit->selectAll(); })`.
    The deferral lets `presentDialog` finish and the double-click's release finish first.
  - Add a fallback in both tools' `keyPress`: if the edit exists and lacks focus, forward printable
    keys, Backspace and Enter to it.
  - Stretch, per spec 7.7: show the editor at the label using the existing `ValueInputOverlay` (one
    `ValueField` anchored at `labelPos`). Decide this after G1 or G2, because the overlay styling
    is shared.
- **Test:** headless QtTest (`test_tools.cpp` has a tool harness). Activate DIMEDIT on d1, check
  that `QApplication::focusWidget()` is the edit, send key clicks "60" and Return, and check that
  the value is 60. Repeat for placing a new dimension.
- **Possible effects:**
  - The focus steal can collide with the command line (G2 `CommandLine.cpp`) if a script or user is
    typing there. Only focus when the tool was activated by a viewer event or double-click, not from
    `runCommandLine` (check `ctx.args`/source).
  - The dialog container belongs to G2 (`CommandDialog.cpp`). No change is needed there. The text
    contrast is UX-13 (G2).

## UX-31 (medium) Rectangle second click ignored; Height box takes focus first
- **Root-cause hypothesis** (the model side is verified, the GUI side is not):
  - `ValueInputModel` activates Width first for the sequence the tool uses (`ValueInput.cpp:87-96`
    and `PointsTool::addPoint`).
  - In SOLID shot 15 the Height box has the active border, so Qt focus went into the Height
    `QLineEdit`. The boxes are child widgets of the viewer with `Qt::ClickFocus`
    (`ValueInputOverlay.cpp:76`), placed at anchor + (18,14) (`ValueInputOverlay.h:81`). They are
    anchored at the cursor and repositioned on a timer, one event late (UX-01).
  - A click on the opposite corner therefore can land on the lagging Height box. The click goes to
    the box, not the viewer: the second click is "ignored", and `FocusIn` makes Height active
    (`ValueInputOverlay.cpp:173-176`). This explains both symptoms.
- **Fix:**
  - Anchor the boxes Fusion-style, away from the cursor: Width at the midpoint of the horizontal
    edge and Height at the midpoint of the vertical edge, outside the rectangle (`RectangleTool::
    preview` passes per-field anchors; `setValue(id, v, anchor)` already supports this).
  - In `ValueInputOverlay`, call `reposition()` synchronously in `sync()` and on anchor change, not
    only on the timer.
  - Make a press on a box while a point tool waits for a click also forward the click to the tool,
    or set `WA_TransparentForMouseEvents` on the frames and keep Tab as the only way into the boxes.
    Prefer the first.
- **Test:** model test for the active index across activate, click 1, create and click 1 again
  (Width each time). GUI check with the xdotool harness after G1's UX-01 fix.
- **Possible effects:**
  - Every PointsTool (circle, polygon, slot, line) uses the overlay. Changing the anchor default
    only for the rectangle avoids churn.
  - `test_value_input` covers the model only.
  - `ValueInputOverlay.cpp` is not in the listed G3 file set but lives in `src/sketch`. Tell G1 and
    G2 that it is touched, because the box styling may be touched by G2 for UX-13.

## UX-28 (medium) Constraint glyphs: letters, tofu Fix, struck-through dimension text
- **Root cause:**
  - `SketchSession.cpp:483-494` renders glyphs as font text: "H", "V", "T", "=", "∥", "◎", "⇄" and
    the emoji `\U0001F512` for Fix, which the viewer font lacks (tofu).
  - `inferenceGlyphText` (`SketchInference.cpp:9-22`) does the same.
  - `drawDimension` (`SketchSession.cpp:640-650`) runs the dimension line through `label`, and the
    text is drawn centred on `label`, so the line crosses the text.
- **Fix:**
  - Add `drawGlyph(kind, at, color)` that builds each glyph from small line primitives sized in
    pixels (`tolerance(p, px)`): an H bar with end ticks, a V bar, ⊥, two parallel strokes, a circle
    with a tangent line, "=" as two strokes, and a lock (a box plus an arc shackle) in `kFixed`
    green. Each glyph sits in a small rounded box, as in Fusion.
  - Use the same helper for the inference glyphs (`SketchToolBase::showInference`).
  - Dimensions: draw the text offset from the line by about 0.6 text height on the side away from
    the measured geometry, or break the line around the text. Use the same offset in
    `dimensionAt()` (`SketchSession.cpp:329-343`) so label picking still works.
- **Test:** there is no rendering test. Add a unit test for the pure glyph segment builder (non-empty
  and bounded), and check visually with the harness.
- **Possible effects:**
  - More preview handles per render. Batch each colour's glyph segments into one `addLines` call.
  - Glyph and constraint picking: if selection uses glyph positions, keep those positions.
  - The font for the remaining texts (dimension values) is G1 UX-12. Do not change the PreviewStyle
    font API here.

## UX-27 (low) a) stale dashed inference line after closing a chain; b) fillet skews a polygon
- **a) Root cause:** `LineTool::addPoint` closes the chain, then `endChain` calls `clearTemp`
  (`CreateTools.cpp:454-459`, `SketchToolBase.cpp:384-388`). `clearTemp` removes the preview
  handles but does not request a redraw. `commitEdit`'s `render()` redraw happened before that, so
  the old guide stays until the next event. This is the same family as UX-01.
  **Fix:** call `viewer_->requestRedraw()` at the end of `clearTemp` when anything was removed.
  **Effect:** an extra redraw request per mouse move (`clearTemp` runs on every move). That is
  cheap if G1 coalesces requests; confirm with G1.
- **b)** Covered by UX-22 fix 2 (polygon `Equal` and `PointOnCurve` on the trimmed vertex).
