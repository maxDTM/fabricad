# G1 fix plan: viewer core (redraw, picking, ViewCube, camera)

Status: plan only, nothing implemented. Line numbers refer to HEAD 78394e9. All paths are under src/viewer/ unless a path says otherwise.
Order: UX-01, then UX-02, then UX-04/05/06 (same mouse code), then UX-07/08, then UX-09..12. Merge G1 first, because G3 and G4 need working picking and redraw to verify their fixes.

## UX-01 (critical) No redraw after scene changes, torn frames, small triad
- Root cause: `ViewerWidget::requestRedraw()` (ViewerWidget.cpp:1270) only calls `OcctView::updateView()`. `paintGL` (occt/OcctView.cpp:236-262) calls `InvalidateImmediate()` and `FlushViewEvents`, so only the immediate layer is redrawn over the old back buffer. `ctx->Display/Remove/SetLocation/SetZLayer/Redisplay(...,false)` in doSync (:713-754), syncOverlays (:772-821), the previews (:1309-1432) and the manipulators (:1480-1533) never invalidate the view. Camera moves do invalidate it, which is why a 1 px pan "fixes" the view.
- Fix: in `requestRedraw()`, call `d_->v3d()->Invalidate()` before `updateView()` when the view is ready. Optionally add a cheap `requestImmediateRedraw()` for the rubber band and for ViewCube hover (QPainter overlay or immediate layer only). In `OcctView::handleViewRedraw`, also `Invalidate()` while `myToAskNextFrame` is set, so every animation frame (ViewCube click, animateTo) is a full redraw. That fixes the torn frame in sketch/71-72.
- Rubber band / sketch preview lagging one position: same cause. Preview updates call requestRedraw, so this is fixed once requestRedraw invalidates.
- Move Component drag shows no live body (AD-8): fixed by the same change if the drag path ends in doSync/SetLocation then requestRedraw. Verify that MoveComponentTool (G4) calls the viewer or document update on each move. If it does not, G4 has to add that call; no change in G1.
- AD-8 triad size: the auto size is `core::kAutoSizePixels = 70` (src/core/Manipulator.h:137, a core file outside every group). Option A (preferred): change it to about 110 px and space the ring and arrows apart in `ManipulatorModel::glyphs`. That is a core edit, so tell G4. Option B (G1 only): add a scale factor (for example 1.6) to one helper, `gizmoPixelSize()`. Use it in syncManipulatorPrs (:1494), refreshManipulatorSizes (:1541) and every manipulator hit-test. Display and hit-testing then stay consistent.
- Possible effects: (1) Every hover and mouse move now does a full redraw, so CPU and GPU load goes up on large models. Use the immediate-only path for hover-only changes and for the rubber band. (2) Headless NullViewer is not affected (requestRedraw only forwards). (3) Tests that count redraws or syncs (test_viewer_smoke checks syncCount_) are not changed. (4) A triad size change moves handle points, so check any test in src/core/tests that asserts handlePoint distances.

## UX-02 (critical) No viewport picking, preselection or window select
- Root cause (most likely): every scene object is shown with `ctx->Display(obj, mode, -1 /*no selection*/, false)` (:735, also :809, 1325, 1344, 1355, 1366, 1382, 1501, 1525). With selection mode -1 the object is never Load()ed into the selection manager. `applySelectionModes()` (:757-768) then calls `ctx->Activate(obj, m, false)`, and on OCCT 7.9.3 that does not register the object with the main selector, so `MoveTo` finds nothing. The ViewCube is shown with selection mode 0 (:413) and is the only object that can be picked.
- Fix: in doSync (:735), call `ctx->Display(obj, dispMode, 0, false)` or `ctx->Load(obj, -1)` first. Then leave `applySelectionModes` to Deactivate everything and Activate the wanted modes. New objects already have `modesValid=false`, so they get the full Deactivate/Activate. Leave overlays, previews, manipulators and labels at -1: they must never be picked (they would hide the body under them).
- Check before closing the issue: first build a GL check. Use the UI harness (tools/uitest/ui.sh, private Xwayland) or a small GL test binary: open the app, make a box, hover the face centre and assert that `ctx->HasDetected()`, `detect()` returns a Face, and `rectangleSelect` over the box returns the body. If detection is still empty, the next suspects are the pixel conversion in detect (:883, DPR) and Activate being called before the object is Displayed.
- Hidden origin planes look highlighted (AD-3): the planes are only collected when `showOrigin || showOriginPlanes` (SceneModel.cpp:289), so a hidden folder should not produce them. The likely cause is the plane-input filter showing them (correct behaviour) together with a stale frame. After UX-01, check this again. If it still happens, make `modesFor` return no modes for items that are not visible.
- Regression test: test_viewer_smoke cannot create GL (no GLX offscreen). Add a test labelled `gui` that runs only when DISPLAY or WAYLAND_DISPLAY is set (through ui.sh), and make it skip otherwise.
- Possible effects: (1) Picks now reach every tool (G3 sketch tools, G4 Fillet/Hole/Joint/Move, Selectors.cpp). Code paths that were only ever fed browser picks get real ShapeRefs with `hasPoint`, `index` and placement. Expect G4 bugs to show up; that is intended. (2) Sketch mode: bodies become pickable under sketch curves. `effectiveFilter` and the order in `detect` (sketch points first) have to keep sketch geometry on top. Check that the profile Top layer picks before the body. (3) Clicking empty space and window select now really replace the selection. ViewCube drag (UX-04) has to be fixed together with this, otherwise cube drags now clear real selections. (4) Selection BVH builds add a little cost on large bodies; this is acceptable. (5) Ghosted bodies get no modes (modesFor :679), which is correct.

## UX-04 (high) ViewCube drag does not orbit and clears the selection
- Root cause: `onMousePress` (:1011-1036) does not check for the cube. The drag passes the threshold in onMouseMove (:1063-1067) and becomes a rubber band, and the release calls `rectangleSelect(Replace)` (:1108-1109). `detect` only reports `onCube` on release (:1111-1113).
- Fix: on a LMB press, run `detect(..., &onCube)`. If the press is on the cube, set `cubePress_`. In onMouseMove, once the drag threshold is passed, set `cubeDrag_` and call `orbitBy(-dx*k, -dy*k, false)` for each move (the helper exists at :467). Skip the rubber band and the tool `mouseMove`. On release with cubeDrag_, do nothing more: no click handling and no selection change. A cube press without a drag keeps the current click behaviour (:1114-1119). Tools must not see a cube press either: return before `manager_->mousePress`.
- Possible effects: orbitBy rotates around the camera centre, not the pick centre. That is fine for the cube (Fusion behaves the same). Orbiting does not change the projection (see UX-08). The right-click cube menu (`rightOnCube_`) is not changed.

## UX-05 (medium) ViewCube small, low contrast, no hover, sticky cyan, small hit zones
- Root cause: cube set-up at :396-413: `SetSize(55)`, `#D9DDE3` on a white gradient, default dynamic highlight (cyan). `SetAllowHighlight(false)` (:457) and the early return for the cube in `detect` (:893-898) mean no hover redraw. Nothing clears the detection after a click or on leave, so the highlight sticks.
- Fix: use `SetSize(80)`, `SetBoxFacetExtension(~14)` and `SetRoundRadius(0.1)`, plus `SetBoxEdgeMinSize`/`SetBoxCornerMinSize` for bigger edge and corner zones. Set font height 13, box colour `#F2F4F7`, inner/edge colour `#9AA4B1` for a visible outline, and text `#2B2E33`. Set the cube's `DynamicHilightAttributes()` colour to a soft blue `#9CC6FF` (shaded, no transparency) and `HilightAttributes()` to the same colour. Raise the TransformPers offset from (85,85) to about (115,115). Call `requestRedraw()` when the hovered cube owner changes. Call `ClearDetected()` after a cube click and in onLeave (onLeave already does it at :1189, but it needs a redraw).
- SKETCH-9 (flat white TOP in sketch view): this is a contrast problem, fixed by the same colours.
- Possible effects: a larger cube covers more of the viewport corner, so check that it does not overlap the floating command dialog (G2/G4 position it). Hit-zone sizes interact with the UX-04 press detection (same code). Use logical pixels times DPR for the offset.

## UX-06 (medium) ViewCube has no home button, roll arrows or step arrows
- Fix: draw the controls with QPainter in `paintOverlay` (:1258), at positions computed from the cube anchor (the same constants as UX-05, in one place). Add hit-testing at the start of onMousePress, before the cube and tools. Home calls `setStandardView(Home, true)`. Roll ±90° is a new `rollBy(deg)` that rotates Up around Direction. The four step arrows show only in face-on views: a ViewerMath helper `faceOnAxis(cam)` (headless-testable in test_viewer_math) finds the view, and each arrow calls `orbitBy(±90,0)` or `orbitBy(0,±90)`. Hover tint on the buttons.
- Possible effects: Qt overlay paint is outside OCCT, so the immediate path is enough for hover. Make sure that clicks on the overlay do not start a rubber band or a tool click (set `suppressRelease_`).

## UX-07 (medium) Fit/Home hides the model behind the nav bar; cube click zooms in too far
- Root cause: `Impl::fitted` (:194-202) uses `FitAll(box, 0.1)` / `FitAll(0.05)` on the whole widget. NavBar (src/app/NavBar.cpp, a G2 file) is an overlay child at the bottom. AIS_ViewCube fits the scene after a click with almost no margin (default `ToFitSelected`).
- Fix: use margin 0.15. Add `ViewerWidget::setViewportInsets(QMargins)`, default bottom = 56 px so G2 does not have to call it. After FitAll, scale by `h/(h-inset)` and shift the centre down by `inset/2 * pixelSize`, in the camera's screen-up direction. Call `cube->SetFitSelected(false)` so a cube click keeps the zoom. To refit on a cube click instead, recompute it with `fitted()` in the animation end camera.
- Possible effects: the home camera saved by Set Home is a copy and is not affected. Tests that compare fitAll camera scale (test_viewer_math does not; check test_viewer_smoke) may need new tolerances. If G2 moves the nav bar, the default inset is wrong but harmless.

## UX-08 (medium) Orbit shows perspective while Orthographic is checked
- Root cause: not confirmed. The screenshot viewer/orbit_shift_mmb.png really does show converging verticals. `projection_` defaults to Orthographic (ViewerWidget.h:238) and onGlInitialized applies it (:416). Candidates: (a) `d_->home` (:1723) or other camera copies taken while the camera was perspective; (b) the AIS_ViewController orbit or AIS_AnimationCamera interpolation producing a perspective camera; (c) MainWindow.cpp:1071 `setProjection(s.projection)` running before GL is ready (then `projection_` is right but the menu and camera do not match). Reproduce first: log `Camera()->ProjectionType()` in `beforeRedraw` before and after a Shift+MMB orbit.
- Fix: add one helper, `assertProjection(cam)`, that applies `projection_`. Call it in `animateTo` (on the target), in `fitted()`, in `setStandardView`/`lookAt`, and in `beforeRedraw` (cheap: compare, then set and Invalidate only if different). setHome stores the camera with the current projection; Go Home re-applies `projection_`.
- Possible effects: the "Perspective with ortho faces" mode in ux.md, if it is ever added, would need an exception. Perspective users are unaffected.

## UX-09 (medium) A hidden selected body is still drawn as a translucent ghost
- Root cause: `syncOverlays` (:780-791) falls back to `core::resolveShape` for refs that are not in `sceneItems_`. That covers face and edge refs (correct) but also bodies that are hidden.
- Fix: before the fallback, require the owner to be displayed. A B-rep ref needs a Body scene item with `ref.owner == r.owner`, and its placement comes from that item. A sketch ref needs its sketch item. Otherwise skip the ref. Do not drop it from the SelectionModel: the browser selection stays.
- Possible effects: highlights for hidden objects in tools disappear, for example a consumed sketch profile that G4 hides (UX-42). This is intended; tell G4. Moved components then use the scene item placement, which is current after doSync.

## UX-10 (medium) Origin planes not shown or pickable during plane input; too large, no labels
- Root cause: showing them when the filter is restricted to planes (:513-526) is correct. They looked missing and unpickable because of UX-01 and UX-02. The size comes from the fixed `opt.originSize = 40` (SceneModel.h:81, used in SceneModel.cpp:297-316). "Only one plane after the Origin eye" is probably the stale frame; check again after UX-01.
- Fix: in doSync, set `sceneOptions_.originSize` from the bounding box of the visible bodies: `max(20, 0.35*diag)`, rounded to 1/2/5×10^n so the geomHash does not change on every edit. Fall back to 40 when there are no bodies. Add three non-pickable AIS_TextLabels ("XY", "XZ", "YZ") at the plane corners, in the UI font (UX-12), only while the planes are shown. Origin planes get the soft blue hover through the normal overlay path (#4FA3FF). Create Sketch on a plane click is handled by the tool (G4/G3) once a pick arrives.
- Possible effects: SceneModel is shared with G4 (UX-42), so G1 only changes the origin block. Size changes recreate the plane objects (new geomHash), so their selection modes have to be applied again (doSync already calls applySelectionModes). test_scene_model checks for origin items and the default size: update any size assertions.

## UX-11 (low) Body shading close to the background; selected body translucent
- Root cause: the material at :605-609 (ambient 0.42, diffuse 0.72) with the default light rig makes top faces near white on the white-grey gradient (paintEvent :1244-1246 and the OCCT background). The selection overlay uses transparency 0.5 (:815).
- Fix: ambient 0.32, diffuse 0.62, and a slightly darker default body colour if it comes from SceneModel colours. Make the selection overlay for faces and bodies opaque or 0.15, with the polygon offset already set. Add the face boundary in `#0B6CFF` for body refs. Keep preselection at 0.6.
- Possible effects: HiddenLine and Wireframe modes use their own colours and are not affected. G2 owns the background gradient; keep the contrast check in sync with G2's palette.

## UX-12 (low) 3D text uses a serif font
- Root cause: AIS_TextLabel at :1376 and :1517 and the ViewCube labels use the OCCT default font. PrimitivePrs and ManipulatorPrs draw no text.
- Fix: add one helper, `viewerFont()`, that returns a family available through `Font_FontMgr` (try "Inter", then "DejaVu Sans", then `Font_NOF_SANS_SERIF`). DejaVu Sans has the constraint glyphs (⊥ ∥ ⌀) that G3 needs (UX-28). Apply it with `SetFont` + `SetFontAspect(Font_FA_Regular)` on all labels, and with `cube->SetFont`.
- Possible effects: G3's constraint glyphs go through showPreviewText, so they get the font automatically. Tell G3 not to set fonts separately. A missing font gives an OCCT warning and a fallback, never a crash. Headless tests are not affected.

## Done (branch ui/G1)

Screenshots: `docs/uiux/fixes/G1/` in the main checkout (not committed). They were taken on display :41 with `QT_SCALE_FACTOR=0.6`, because the tiled Xwayland window was only 945 px wide and the app does not fit at scale 1. The before/after pairs come from the same document (`bracket.fcad`). Note: `before-hover-face`/`before-click-face` hovered just outside the face, so only the baseline cube drag (`before-cube-drag`, which draws a rubber band) is a real "before". Picking was confirmed broken before the fix by the earlier gdb sweep.

- **UX-01 (redraw):** `requestRedraw()` now calls `OcctView::redrawAll()`, which invalidates the view before update. A new `requestImmediateRedraw()` is used for hover, the rubber band and cube controls. `OcctView::handleViewRedraw` invalidates the view on every animation frame. Triad: plan option B (G1-only). `gizmoPixelSize()` = pixelSize × 1.6, and the viewer's own `gizmoPress/Move/Release` use it for both drawing and picking. Verified: eye toggle, rubber band, line preview (no lag), cube animation and live body during a Move Component drag all redraw at once (`after-hidden-selected-body`, `after-line-preview`, `after-move-component-*`). Caveat for G4: `part/tools/FeatureValueBox.cpp` anchors on `handlePoint(.., viewer->pixelSize())` without the ×1.6. Linear arrows are unaffected unless their tip depends on the size.
  Files: `ViewerWidget.cpp/.h`, `occt/OcctView.cpp/.h`.
- **UX-02 (picking):** doSync displays scene objects with selection mode 0 instead of -1; `applySelectionModes` then sets the wanted modes. Hover, face click, window select and origin-plane pick all work (`after-hover-face`, `after-click-face`, `after-window-select*`, `after-origin-plane-hover`). New `gui`-labelled test `fabricad_viewer_test_viewer_gl` runs only with `FABRICAD_GL_DISPLAY=:N` and skips otherwise; it passes on :41. AD-3 was not seen after the fix.
- **UX-04 (cube drag):** a left press on the cube is captured before tools and selection. A drag orbits with `orbitBy` (0.5°/px) and a click rotates to the clicked cube part. The selection is kept (`after-cube-drag-released`). A double-click on the cube counts as two clicks.
- **UX-05 (cube look):** size 80, facet extension 14, round radius 0.1, minimum edge/corner sizes, box `#F2F4F7`, outline `#9AA4B1`, sans font 13, soft blue `#9CC6FF` hover. The hover tint repaints when the hovered part changes, and the detection is cleared after a click and on leave (no sticky cyan). Offset is 115 px. Note: OCCT sizes the cube in device pixels, so it looks large at DPR 0.6; at DPR 1 the face is about 108 px. The OCCT dynamic hover highlight of bodies is drawn above the cube (immediate layer); this is minor and not fixed.
- **UX-06 (cube controls):** QPainter overlay with home, two roll arrows (±90° `rollBy`) and four step arrows that appear only in face-on views (`isFaceOnView` in ViewerMath, tested headless). Controls highlight on hover and are hit-tested before the cube, tools and selection. Verified: step right → RIGHT, roll, home (`after-step-right`, `after-roll`, `after-home`).
- **UX-07 (fit):** fitting uses `FitMinMax(margin 0.15)` plus `applyViewportInset` (ViewerMath, tested headless). The default bottom inset is 56 px, settable with `setViewportInsets()`. The ViewCube is now an `AIS_ViewCube` subclass whose `viewFitAll` uses the same fit. Deviation from the plan: the cube click re-fits with a margin instead of using `SetFitSelected(false)`, because OCCT always fits after a cube click.
- **UX-08 (projection):** all camera animations go through `animateCamera()`, which copies the target and re-applies the chosen projection. The cube fitter and `beforeRedraw` also re-apply it, and a drift is logged as "camera projection drifted". The perspective issue was not reproduced: a Shift+MMB orbit stays orthographic and no drift was logged.
- **UX-09 (hidden ghost):** overlays for refs that are not themselves scene items are drawn only when their owner (body, sketch or feature item) is displayed and not ghosted, and they use that item's placement. Component refs expand to their bodies. Verified with `after-hidden-selected-body`.
- **UX-10 (origin planes):** the plane half size is `originPlaneHalfSize(diag)` = max(20, 0.35 × diag) on 1-2-5 steps, or 40 without bodies. It is computed in doSync from the visible bodies (SceneModel itself is unchanged). There are non-pickable XY/XZ/YZ labels in the UI font. A plane click starts the sketch (`after-sketch-started`). There is a new smoke test.
- **UX-11 (shading):** body material is now ambient 0.32 / diffuse 0.62. The selection overlay is at 0.15 transparency (was 0.5), with a 2 px `#0B4FC0` outline on whole bodies (`after-body-selected`).
- **UX-12 (font):** `viewerFont()` picks Inter, else DejaVu Sans, else OCCT's sans alias. It is applied to preview text, manipulator labels, origin labels and the ViewCube.
- **Tests:** full `ctest -j2` (offscreen) passes 55/55. The GL test passes on :41.
