# Redesign phase 1 (shell): what was built and checked

Branch `ui/shell`. Plan: `docs/plans/ui-redesign.md` 5.1, 6.1, 6.2, 6.5, 8.2 and the phase 1 row of section 10.

## Built
- **Title bar** `#AppBar` (36 px): logo menu (the File menu), workspace selector `#WorkspaceSwitcher`
  (PART / ASSEMBLY / DRAWING with a keycap), angled document tabs `#DocumentTabs` (`DocumentTabBar`,
  painted trapezoids, 2 px accent on the active tab, neutral unsaved dot, decision 11), `#NewTabButton`,
  search box `#SearchBox` (opens the S-box), undo, redo, save and help.
- **Workspace selector**: Part and Assembly are toolbar filters of the Design workspace (decision 2,
  `ui/designFilter`); Drawing opens the drawing tab. Shortcuts are **Alt+1 / Alt+2 / Alt+3** (tentative,
  defined once in `kWorkspaceShortcuts` in `src/app/TitleBar.h`). Ctrl+1 stays the Front view.
- **MainToolbar** (`src/app/MainToolbar.*`, replaces `Ribbon`; `Ribbon.h` stays as an alias) in the
  non-movable QToolBar `#MainToolbarHost` at the top. It has labelled sections with straight dividers:
  SKETCH, CREATE, MODIFY, ASSEMBLE, CONSTRUCT, INSPECT, MORE (one dropdown per folded tab or group:
  INSERT, SELECT, TOOLS, SURFACE when registered) and DOCUMENT on the right (Params, Settings).
  - While a sketch is open, the contextual SKETCH page shows CREATE, MODIFY, CONSTRAINTS (small icon
    grid), INSPECT, MORE (OPTIONS, SELECT, TOOLS) and FINISH SKETCH.
  - The Assembly filter puts ASSEMBLE first with up to 6 tools. SKETCH, CREATE and MODIFY collapse
    to their captions. The rules are one table in `ToolbarModel.cpp`.
  - Collapse: when the row is too narrow, the right-most buttons of the fullest sections fold into
    the caption dropdowns first. Then whole sections collapse to a caption button, by priority.
    The toolbar never scrolls and never cuts a label (`fitToolbar`, unit-tested). It fits at
    1280 px and still works at 900 px.
  - Test and tutorial hooks (8.2): `toolId` is set on every tool button and dropdown action.
    `toolbarTab` and `toolbarGroup` are set on every section and caption. MORE buttons carry
    their registry tab (`tab:TOOLS`). The objectNames `RibbonRow`, `RibbonGroup`,
    `RibbonGroupLabel`, `RibbonTool` and `FinishSketchButton` are kept.
- **Status bar** (28 px). It holds these cells:
  - the active command (gold bar, gold square and name);
  - the prompt (caps, elided);
  - key hints (keycaps such as `ENTER APPLY`, `ESC CANCEL` and `TAB NEXT FIELD`);
  - the message (as typed);
  - the command line `[> ... HISTORY ^]` (`#CommandLine` kept);
  - OCCT version, units (lowercase), GRID with its spacing (click toggles), SNAP (click toggles),
    the rebuild meter (8 bars and the last recompute time) and the selection.

  Narrow windows drop OCCT first (< 1500 px), then the hints (< 1350), the rebuild meter (< 1150) and
  the search text (< 1100).
- **UiSettings** (`src/app/UiSettings.*`): every `ui/*` key of 6.1, plus `ui/glow`, `ui/scanlines`,
  `ui/designFilter` and `ui/commandLine`. Values are validated and normalised, `changed(key)` is a
  live signal, and garbage in the file reads as the default. `ui/theme` and `ui/fontScale` apply live.
- **Preferences** gets an **Appearance** page and a **Layout** page:
  - Appearance: theme Dark / Light / Follow system (live), UI scale, glow and scanlines.
  - Layout: toolbar, sidebar, command card, quick toolbar, orientation, timeline and "remember
    dragged card", with a live preview thumbnail.

  Phase 1 applies the theme, the scale and the toolbar at the top. The other values are stored for
  phases 2 to 4. The THEME command goes through UiSettings, so the page stays in step.
- `saveState` / `restoreState` use layout version 2, so a ribbon-era layout resets to the defaults (6.5).

## Verification
- **ctest**: 60 of 60 pass, offscreen.
- **Colour lint** (`theme_color_lint`) and `theme_tokens` pass.
- **New tests**:
  - `test_app_logic`: sections, fit, short labels, UiSettings, status cells.
  - `test_main_window`: hooks, 1280 and 1920 fit with no cut labels, workspace selector and Alt+2,
    status cells, Preferences pages.
  - `test_theme_manager`: user data keeps its case in the file dialog, completer, status message and
    tabs; theme switch time. The best of 6 switches is under 150 ms (about 80 ms). The median varies
    with machine load.
- **GUI** on display :63 (`ui.sh`). The Xwayland window is tiled by the compositor (945 × 490, later
  945 × 990), so the run used that size. The flow covered the workspace menu, CREATE and MORE
  dropdowns, Alt+2, sketch, rectangle, Finish, Extrude 25, save and open with a mixed-case path,
  Preferences (Appearance > Light live, Layout changes and reset), and the light sketch page. The
  screenshots are `p1/gui-*.png`.
- **Exact 1920 × 1080 and 1280 × 800**: offscreen grabs through a script (`FABRICAD_WINDOW_SIZE`, a
  new developer aid in `main.cpp`). The chrome is real; the 3D view is blank offscreen. Screenshots
  are `p1/offscreen-{dark,light}-{1920x1080,1280x800}-{1-idle,2-assembly,3-sketch,4-extrude-command}.png`.
