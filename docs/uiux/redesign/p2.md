## Command card interface (for the card agent, phase 3)

Everything is on `SidebarHost` (`src/app/SidebarHost.h`); get it with `MainWindow::sidebarHost()`.

```cpp
QWidget* SidebarHost::cardSlot() const;            // #CardSlot, first splitter pane, hidden while empty
bool     SidebarHost::canDockCard() const;         // false: sidebar hidden or a drawing tab -> float (6.4)
void     SidebarHost::dockCard(QWidget* card);     // reparent + show in the slot; FEATURES -> header + live row
void     SidebarHost::releaseCard(QWidget* newParent = nullptr);  // hide + reparent; FEATURES and sizes restored
QWidget* SidebarHost::dockedCard() const;
void     SidebarHost::setFeatureSelectionActive(bool on);  // force-expand FEATURES (optional, see below)
bool     SidebarHost::featureSelectionActive() const;
void     SidebarHost::setDropHighlight(bool on);   // dashed accent outline over the drop target (#CardDropHighlight)
QRect    SidebarHost::cardDropRect() const;        // global rect of the drop target (slot, or FEATURES when empty)
signals: cardDockAvailabilityChanged(bool), featureSelectionChanged(bool)
```

Contract:
1. **Placement `sidebar`**: when a command starts and `canDockCard()`, call `dockCard(card)`; on finish call
   `releaseCard(viewportOverlayParent)` (or `nullptr`). Listen to `cardDockAvailabilityChanged(false)` (sidebar
   hidden, drawing tab) to fall back to `floatRight` / `floatLeft` without changing `ui/cardPlacement`.
2. **Size**: the slot gives the card `max(card->sizeHint().height(), card->minimumSizeHint().height())` or more
   (everything FEATURES gives up). The card should scroll its body itself when it gets less (it already has
   `#CommandDialogScroll`). Width = the sidebar width (320 default, 260 minimum).
3. **FEATURES while docked**: it folds to its header plus the live row (`FeatureListWidget::compactHeight()`),
   which the shell fills from the active command (`updateLiveRow`). The card does not need to do anything for it.
   To show the value the user is typing in the live row, call
   `mainWindow->featureList()->setPendingLive(FeatureListModel::PendingLive{name, icon, value})` (optional).
4. **Feature-selection inputs** (Mirror, patterns): the sidebar detects them by itself from the active
   document's `SelectionModel::filter()` (a filter other than all kinds that contains `ShapeKind::Feature`),
   and expands FEATURES (also when the user collapsed it), then folds back. While the card is docked, MODEL and
   SELECTION fold to their headers for that time (the user's collapse state is kept and restored). If the card's input works differently,
   call `setFeatureSelectionActive(true/false)`; either source expands.
5. **Drag to dock** (6.4): while dragging the card header call `setDropHighlight(true)` and test the cursor against
   `cardDropRect()`; on drop inside, store `ui/cardPlacement = sidebar` and `dockCard()`.
6. In the `strip` timeline style FEATURES is hidden and the card simply takes the top slot above MODEL (6.4).

Findings fixed during the run:
1. Enter in the rename editor reached the list and started editing the feature: the editor now takes Return / Enter /
   Escape itself (also on `ShortcutOverride`).
2. The inline tip as a child widget next to the native OCCT view could take the X pointer grab, so the first click
   after a hover could be lost: the tip is now a tool-tip window, and the drag refusal is painted inside the list.
3. The current ROLLBACK row stayed gold after a drag and read as "still dragging": gold only on hover and drag; the
   focus ring marks the current row.
4. Panels kept their pixel sizes on small windows: sizes now scale in proportion to the sidebar height.
5. Shift+Tab from the list did not reach the headers: explicit tab order (header, search, filter, list, MODEL header, eye,
   tree, SELECTION header).

Notes (not sidebar code):
- `import -window root` on the rootful Xwayland display often returns a stale frame until the pointer moves; the
  screenshots were taken after a 1 px pointer nudge, and states were re-checked after hovering the list.
- At 466 px window width the dock cannot keep its 260 px minimum and the MODEL eye column is cut at the edge; not
  reachable at the 1280 px minimum the shell targets.
- The FEATURES filter button reuses the `select-filter-all` glyph (a funnel with a check); a plain funnel icon is
  an icon-set item for phase 5.
