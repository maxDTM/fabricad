## PART-01 (high): modeled thread on a plain cylinder fails
- Root cause (likely, confirm with a test): `makeThreadCutter` (src/part/ExtraUtils.cpp:250-257) puts a profile vertex exactly on the
  nominal radius (`rMaj` for external threads, `rMin` for internal ones). With Auto size on, nominal == cylinder radius (D10 -> M10),
  so the helical edge swept from that vertex lies on the body's cylinder face. OCCT then gets edge-on-surface tangency, and
  `runBoolean` (src/part/PartUtils.cpp:206) rejects the result after `unifyWithHistory`. The existing test only covers a D6 rod
  (test_primitives_thread.cpp:241), so this case is not tested.
- Fix:
  1. Add a test: Cylinder D10 H20 with a full-length modeled thread, both ends open. It must give a valid solid with lower volume.
  2. Pass the real cylinder radius to `makeThreadCutter` and move the kink off the surface (rMaj + 0.05P, or cylR + 0.05P if larger).
     Clamp the groove width at the outer radius to 0.95P or less, so neighbouring turns never touch: a straight flank continued
     out to rMaj+ext is wider than P and self-intersects. Mirror this for internal threads at rMin.
  3. Call `booleanOp(Cut, ..., unify=false)` from Thread.cpp:237. Unify on helical faces is slow and a known source of invalid
     results. If the result is still invalid, try a ShapeFix_Shape pass (same as Fillet `healed`) before reporting an error.
  4. Check the cutter itself with `isValidShape` and report "thread cutter invalid" separately, so the error message points at
     the right step.
- Effects: Hole's tapped/modeled thread (`threadModeled`, test line 336) uses the same cutter, so run the hole tests too.
  Thread depth changes slightly (≤0.05P), so update any volume assertion with tight tolerances. unify=false leaves more faces,
  which can shift topological names of later features on threaded bodies. Only new models are affected; saved models
  recompute with the new names, so check the test_part_smoke fixtures.

## PART-02 (medium): invalid expressions coerced silently, OK stays enabled
- Root cause:
  - PropertyPanel.cpp:150-156: on an eval error, `applyNumericText` only paints a red border.
  - PropertyPanel.cpp:187-190: `editingFinished` then overwrites the text with the last good value, and the tool's `valid_`
    stays true.
  - FeatureValueBox.cpp:107-115: the Commit path (Enter in the on-canvas box) also ignores a failed eval and calls
    `tool_.accept`.
- Fix:
  1. PropertyPanel keeps `std::map<std::string, std::string> invalid_` (property name -> error). It is set on eval failure and
     cleared on success. When the set changes, emit `validityChanged()`. `editingFinished` leaves invalid text in place
     (red, with the error as tooltip) and does not reset it.
  2. In FeatureTool, after computing `valid_` (FeatureTool.cpp:593), use `valid_ && !(panel_ && panel_->hasInvalid())`. Show
     the message as "<Label>: <eval error>" with error style. `accept()` (line 751) checks the same condition.
  3. FeatureValueBox: on Commit with text that does not evaluate, show the error (`ctx.showMessage(err, true)`) and do not
     accept.
- Effects:
  - The panel can be null in headless tests: guard it, and tests that drive `setNumeric` keep their behaviour.
  - Rebuilds (`rebuild()`) must drop `invalid_` entries for rows that no longer exist. Otherwise a hidden field could block
    OK forever.
  - Sketch dialogs reuse ValueInputOverlay (G4's file): change only FeatureValueBox, not the overlay.
  - The command line already reports errors through `setNumeric`.

## PART-03 (medium): one profile click previews every profile
- Root cause: Extrude's `profiles` input accepts `Profile|Face|Sketch` (Extrude.cpp:19). With Sketch in the mask,
  ViewerWidget `modesFor` (ViewerWidget.cpp:826-829) makes sketch curve presentations pickable as a whole sketch (mode 0).
  `ownerToRef` (line 1054-1064) then returns `ShapeRef::sketch`. A click near or on a curve (text, spline, ellipse:
  ADVANCED-SKETCH-8 shots 190/198) gives a Sketch ref. `profileFaces` (PartUtils.cpp:539-549) expands it to all profiles,
  and the panel shows "1 selected".
- Fix:
  1. In `modesFor`, when the effective mask contains Profile, do not activate whole-sketch mode 0 on sketch curve
     presentations. Profile presentations already cover the click.
  2. In `ownerToRef`, when Profile is allowed and the hit lies inside a profile region, return
     `sk->profileRef(*sk->regionAt(local))` instead of the sketch.
  Whole-sketch selection then stays possible only from the browser or by preselection.
- Effects:
  - Revolve, Sweep and Loft profile inputs and the primitives' plane input (`kPlaneInputKinds` includes Sketch) use the same
    mask logic. Plane pick on a sketch must still work from the browser. Check that Sketch on a sketch's curves (planes) is
    still possible.
  - Clicking exactly on an open curve now selects nothing in Extrude. That is acceptable and matches Fusion.
  - Interacts with G4 SK-07 (SketchProfiles regions): after the merge, retest the polygon and construction-circle profiles
    and the multi-profile sketch.

## PART-04 (medium) + PART-07 (low): dialogs pre-fill a previous value / Torus 50 > 40
- Facts:
  - The Torus defaults are 40/10 (Primitives.cpp:169-170).
  - No feature-level value memory exists: `applyDefaultsForNewFeature` only sets the operation.
  - FeatureTool resets the value box on `activate` and `deactivate`.
  So the stale value comes from outside the feature.
- Candidate causes (reproduce before fixing; log `ctx.args` in `FeatureTool::startWith`):
  1. `ToolManager::repeatLast` (core/Tool.cpp:347-351) replays `lastArgs_` (stored at line 373). Enter, Space, or the
     marking-menu "Repeat" therefore re-runs `EXTRUDE -8` / `OFFSETPLANE -12` and `startWith` applies args[0] to the primary
     numeric (FeatureTool.cpp:164-167).
  2. Keyboard focus stays in the dialog when the next command opens (CommandDialog::present, app/CommandDialog.cpp:104
     "the keyboard focus stays where it is"). Typed digits then land in a new panel field rather than the viewport value
     box. This would explain 50 in "Torus diameter" after typing 50 in Sphere's Position X (shots s10/s13).
  3. PressPullTool::activate (FeatureTool.cpp:860) skips the state reset that `FeatureTool::activate` does (valid_, outcome_,
     message_, flip flags). This is harmless for values but should be made consistent.
- Fix:
  - `repeatLast` repeats the command without its numeric args. Keep args only for non-numeric ones such as file paths, or
    let the tool opt in. Update core/tests/test_tool.cpp:135-140.
  - `CommandDialog::present` moves focus to the viewport when the old focus was inside the dialog. Do not take focus from
    the command line.
  - PressPullTool::activate calls a shared `resetState()`.
  - Torus: also guard defaults in `TorusFeature`. If minor ≥ major on a new feature, clamp minor to major/4 in
    `applyDefaultsForNewFeature`. New features only, so edits are never changed.
- Effects:
  - The scripted/typed `EXTRUDE 10` keeps working (first run). Only the repeat changes.
  - core/Tool.cpp and CommandDialog.cpp are not in any group's list, so take ownership here and tell G1/G2 (MainWindow
    connects CommandDialog).
  - Focus change: Esc and Enter must still reach the tool (SK-08 logic in `dismiss`). Retest Enter-to-OK.

## PART-05 (medium): Paste New of a copied body does nothing
- Root cause:
  - `assembly.copy` is enabled only with a component selection (AssemblyModule.cpp:128-132, `hasComponentSelection`). Ctrl+C
    on a body runs nothing and gives no message, because the disabled shortcut is silent.
  - Paste/Paste New are enabled only when the component clipboard holds live components (AssemblyModule.cpp:141-160), so
    they are silent too.
- Fix:
  1. Add a body clipboard next to `componentClipboard()`. `copySelectedComponents` copies bodies (from preselection or
     selection) when no component is selected, with the message "Copied Body7".
  2. Enable copy on any selection. For unsupported kinds (faces) show "Select a body or component to copy".
  3. Paste / Paste New with bodies: inside one snapshot undo step, add a `BaseBodyFeature` (frozen copy, already exists in
     src/assembly/BaseBodyFeature.h) per body into the active component. Select it and start Move as Paste does for
     components.
  4. Paste with an empty clipboard: enable the tool and report "Nothing to paste".
- Effects:
  - The Ctrl+C shortcut is shared. Make sure sketch-mode copy (if any) and text fields still win: check ShortcutRouter
    (G2's file), read-only.
  - BaseBody adds a timeline item, which is expected. Undo of a paste must remove both the body and the move.
  - Assembly tests that assume Paste is disabled with an empty clipboard need updating.

## PART-06 (medium): Thread dialog shows no size/designation/class fields when Auto size is off
- Root cause: `ThreadFeature::updatePropertyFlags` unhides `designation` correctly (Thread.cpp:183). However,
  FeatureTool's panel `valueChanged` handler rebuilds the panel only for Enum changes (FeatureTool.cpp:720, 733). A Bool
  toggle (Auto size, Full length) changes hidden flags without a rebuild, so the rows never appear. The same bug hides
  Length/Offset after "Full length" is unchecked, and affects any bool-gated field in other features.
- Fix:
  1. In `updatePreview`, or in the panel handler, compare the set of visible property names before and after
     `updatePropertyFlags()`, and call `panel_->rebuild()` when it differs. Restore focus to the toggled widget by
     objectName.
  2. Fusion-like fields for Thread:
     - Size: nominal-diameter enum.
     - Designation: pitch options filtered by size; keep the existing `designation` property for file compatibility.
     - Class: `threadClass` enum, 6g/4g6g/6e for rods and 6H/5H for holes, defaulting to 6g/6H.
     `ThreadInfo::callout()` uses the class. Add old-file migration: a missing `threadClass` falls back to the default.
- Effects:
  - A generic rebuild-on-visibility-change also fixes other features (Hole, Pattern direction2, and so on). Rebuild deletes
    widgets later (`retireFormRows`), which is safe inside signals.
  - Watch for the panel losing a partially typed numeric text in another field: only rebuild when visibility changed.
  - test_tools / test_value_box may count panel rows.

## PART-08 (low): 2 mm fillet on a split + drafted box edge fails as invalid shape
- Root cause (to confirm): one of three checks after `mk.Build()` rejects the result (Fillet.cpp:200-210):
  `sameKindSolid`, `hasSelfIntersection` (PartUtils.cpp:317, BOPAlgo_ArgumentAnalyzer with kFuzzy), or the healed
  BRepCheck. Drafted faces from BRepOffsetAPI_DraftAngle carry large tolerances, and the split leaves coplanar face pieces.
  Both commonly produce false positives in the self-intersection analyzer or invalid edges in the fillet.
- Fix:
  1. Add a headless test reproducing box -> Split Body -> Draft -> 2 mm fillet on a vertical edge, and log which check
     fails.
  2. Before filleting, clean the body with ShapeUpgrade_UnifySameDomain (merges split coplanar faces; history must be mapped
     like booleans do) and `ShapeFix_Shape`, plus `BRepLib::OrientClosedSolid` if needed.
  3. Run `hasSelfIntersection` only when BRepCheck fails after healing, not on every result.
  4. Make the error name the failing check.
- Effects: Fillet, Chamfer and variable fillet share the path (Chamfer uses the same checks at lines 301-308). Unify on
  input changes face names, so dependent features need to map history through `History::of`. Relaxing the
  self-intersection check could accept a truly bad fillet: keep the volume-jump check (line 205-209) as a safeguard.

## PART-09 (low): Faces filter shows hidden origin planes; Fillet button stays highlighted
- Root cause:
  - `ViewerWidget::onFilterInputsChanged` (ViewerWidget.cpp:647-660) forces `showOriginPlanes` whenever the combined mask is
    restricted and contains OriginPlane, regardless of whether a tool asks for a plane. When idle,
    `finishActive` (core/Tool.cpp:368) sets the tool filter to the user's effective filter, so a user filter, or a filter left
    over from a plane-input tool, turns the planes on while the Origin eye is off (shot 153).
  - Ribbon buttons are checkable (Ribbon.cpp:257-259). The click toggles the check state before the tool runs.
    `refreshStates` only runs on some paths: it is not called when the tool is rejected (disabled or instant) or finishes in
    a background tab (MainWindow.cpp:870-873).
- Fix:
  1. Viewer: show origin planes for picking only while a tool is active and its own filter (`toolFilter_` set by the tool)
     contains a plane kind. Add an explicit `setToolActive(bool)` from ToolManager toolActivated/toolFinished, or compute it
     from `toolFilter_ != effectiveUserFilter`. When idle, use the browser Origin visibility only.
  2. Ribbon (G2's file, coordinate): call `refreshStates()` after every click (queued) and on every `toolFinished`.
- Effects: plane-input tools (Offset Plane, primitives' plane, Sketch) must still show planes when Origin is hidden, so
  test them. Ribbon.cpp belongs to G2: hand them the 2-line change or apply it after their merge.

## PART-10 (low): 500 coincident pattern bodies, no warning, z-fighting, slow redraw
- Root cause: `linearOffsets` (Pattern.cpp:400-421) only rejects step < 1e-9. Extent with a small distance and quantity 500
  creates nearly coincident bodies, and there is no overlap check before `applyTransforms`.
- Fix: in Rectangular and Circular pattern compute, compare the instance step with the tool/body extent along the direction
  (bbox projection). If step < 1e-3 mm (coincident), error "instances coincide (spacing X mm)". If step < extent, warn
  "pattern instances overlap" for New Body. Overlap is fine for Join, so only warn. Circular: same check using the chord
  between instances.
- Effects: overlapping Join patterns, a normal use, must not warn. Only warn when the operation is New Body or components.
  The redraw lag with 500 bodies is a separate viewer performance issue and is out of scope; note it.

## PART-11 (low): seam edges drawn on curved primitives
- Root cause: body presentations use `SetFaceBoundaryDraw(true)` (ViewerWidget.cpp:462, 751, 790, 1721). OCCT draws every
  face boundary, including seam edges of closed surfaces (sphere, torus, cylinder, cone).
- Fix: on those drawers call `SetFaceBoundaryUpperContinuity(GeomAbs_C2)` (OCCT ≥7.5; check the installed version). Run
  `BRepLib::EncodeRegularity(shape, angTol)` once when the presentation shape is built, so seams (CN) and smooth tangent
  joins are tagged and skipped. Alternative without touching the shape: build our own boundary compound that skips edges
  where `BRep_Tool::IsClosed(edge, face)` is true.
- Effects: EncodeRegularity mutates the shared TShape edge regularity flags (metadata only), so prefer running it on a
  copy, or use the IsClosed alternative. Tangent fillet edges may disappear too if C1 is excluded. Fusion shows tangent
  edges, so use the seam-only filter if the continuity threshold hides them. Also check HiddenLine mode and the selection
  highlight (line 995).

## PART-12 (low): first face click in Offset Plane sometimes not registered
- Root cause (likely): starting a plane-input tool toggles `showOriginPlanes`/`showProfiles` (ViewerWidget.cpp:653-657),
  which calls `scheduleSync()` and rebuilds presentations asynchronously. A click that arrives before the sync, or while
  `applySelectionModes` has not yet run on new objects, picks a stale or removed owner and `detect` (line 1078) finds
  nothing usable. The second click works.
- Fix: in `detect()` (and the release path that calls `defaultClickSelect`), call `doSync()` first when `syncPending_` is
  true, so picking always runs on the current scene and selection modes. Add a test: start Offset Plane and immediately send
  one click on a face. Expect "1 selected".
- Effects: a synchronous sync on click costs one rebuild that would have happened anyway. Make sure `doSync` is not
  re-entered from inside a tool's selection callback (guard it). Also helps the "quick second click ignored" note in
  general-bugs.
