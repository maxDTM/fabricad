Plan only, nothing implemented. Line numbers are from the tree as of 2026-10-22 07:05.
Sources: round1/app-tools.md, general-bugs.md (GB-5), advanced-sketch.md (AS-10, AS-14) and screenshots 113, 114, 117, 152, and advanced-sketch/173.

## APP-01 (high): renaming a parameter to an existing name overwrites the other one
- **Root cause:** `src/app/ParametersDialog.cpp:69-74` builds a rename as a macro: `SetParameterCommand(name)` then `SetParameterCommand(oldName, "")`. It never checks whether `name` already exists, so `Document::setParameter` (`src/core/Document.cpp:677`) updates the existing row in place and the old row is then removed.
- **Fix:** in `onCellChanged`, column 0, if `name != oldName && doc_.parameter(name)`, reject: show "A parameter named 'x' already exists", then queue `reload()` to put the old name back. Show the message in a red `QLabel` above the buttons, not in a modal `QMessageBox`, because a modal box would block headless or scripted tests. Clear the label on the next successful edit.
- **Possible effects:**
  - `reload()` runs inside `cellChanged`. Keep the existing `QueuedConnection` so the table is not rebuilt during the item's own edit.
  - Undo is unchanged, because nothing is pushed.

## APP-02 (high): renaming to an invalid name deletes the parameter
- **Root cause:** the same macro. `setParameter` returns false for an invalid name (`Document.cpp:678`), so nothing is added, but the second command still removes `oldName`. `SetParameterCommand::redo` (`src/core/Commands.cpp:121`) ignores the return value.
- **Fix:** in the dialog, check `core::isValidParameterName(name)` (`src/core/Expression.h`) before building the macro. On failure, show "invalid name: identifiers are letters, digits, _; not a unit/function" and reload. Also, defensively, make `SetParameterCommand::redo` a no-op when `setParameter` fails. Use the same check for `SET name=` in `src/app/AppTools.cpp:167`, before pushing.
- **Possible effects:**
  - Changing `Commands.cpp` touches core. `SetParameterCommand` is also used by `SET` and `addParameter`, and an invalid `SET` already reports "invalid parameter name", so behaviour stays the same there.
  - The core and app tests for `SET` should still pass. Add a test: rename to "my var" or "mm" keeps the old row.

## APP-05 (low): a parameter in use can be removed
- **Root cause:** `ParametersDialog::removeSelected` (`:91`) and `SET name=` with an empty value (`AppTools.cpp:168`, empty `expr` means remove) never look for references.
- **Fix:** add an app-side helper, `parameterUsers(doc, name)`, in `ParametersDialog.cpp` or `AppActions`. It runs `core::referencedParameters()` over:
  - other parameters' expressions;
  - every `Feature::properties()` that has an expression;
  - the constraint `expression` strings of sketch features, read through `dynamic_cast<sketch::SketchFeature*>` (read-only, no change to G4 files).

  If the list is not empty, refuse with "Used by Extrude1, Sketch2, half". This matches Fusion, which disables delete for parameters in use. Apply the same check to renaming a used parameter: refuse rather than leave dangling references. Rewriting references on rename is a later follow-up.
- **Possible effects:**
  - It does not touch Feature.cpp (G1) or SketchFeature.cpp (G4); the app already links the sketch module (check the CMake dependency).
  - Refusing a rename is stricter than today, but today's rename silently breaks the dependent features, so this is strictly better.
  - Scripts that use `SET p=` to remove a used parameter now fail (no known test does).

## APP-03 (medium): no Preferences or units dialog; TOOLS tab has only Export
- **Root cause:** only `assembly.export-*` (`src/assembly/AssemblyModule.cpp:180,192`) declare `tab = "TOOLS"`. `app.parameters` is `SOLID > MODIFY` only (`AppTools.cpp:153`). There is no preferences tool, the status-bar `unitsLabel_` is a plain `QLabel` (`src/app/MainWindow.cpp:366`), and `Document::setUnits` (`Document.cpp:84`) has no undo command.
- **Fix:**
  1. Add new `src/app/PreferencesDialog.{h,cpp}`, a modeless dialog with these pages:
     - General: default units for new designs, reverse zoom (`ViewerWidget::setReverseZoom`), zoom to cursor.
     - Document: length and angle units of the active document.

     Store settings in `QSettings` under `prefs/*`.
  2. Add `SetUnitsCommand` in `core/Commands.cpp` (old and new `UnitSystem`; redo and undo call `setUnits` and `recompute`).
  3. Add tools in `AppTools.cpp`:
     - `app.preferences` ("Preferences", aliases PREFERENCES and PREFS, not OPTIONS, which is `app.options`), placed in TOOLS > UTILITIES.
     - `app.units` (UNITS, see APP-09).
  4. Show Parameters in TOOLS too, without duplicating the tool, through an extra-placement table in `src/app/ToolbarModel.cpp` `buildToolbarModel`, for example `{"app.parameters","TOOLS","UTILITIES"}`. Add "UTILITIES" before "EXPORT" in `orderedGroups`.
  5. "Scripts" (run a `.fcs` file through `ScriptRunner`) is optional and can be deferred.
  6. Make the status-bar units label clickable so it runs `app.units`. This needs a small hook in `MainWindow.cpp`, which G1 owns (see coordination).
- **Possible effects:**
  - Bare numbers in expressions use the display unit (`Expression.h` header). Changing document units therefore re-evaluates parameters such as "10" to 10 in, which changes geometry. Before or while switching units, add the old unit to bare-number parameter expressions (part of the same `SetUnitsCommand`), or warn the user. Test it.
  - `QSettings` in headless tests: tests must set their own organisation name or test mode so they do not read the user's real preferences.
  - Ribbon or main-window tests that count tabs, groups or buttons may need updating.
  - Do not apply preferences at startup inside the `MainWindow` constructor without coordinating with G1.

## APP-04 (medium): Appearance has no A shortcut, is not in MODIFY or search; A in the browser starts type-ahead
- **Root cause:** Appearance exists only as a browser context-menu action (`src/app/BrowserTree.cpp:522`, `pickBodyAppearance` `:578`); no tool is registered. With browser focus, `isCanvasFocus` (`MainWindow.cpp:1719`) routes A as a shortcut. No tool matches, so the key falls through to `QTreeWidget::keyPressEvent` (`BrowserTree.cpp:622`) and its keyboard search, which jumps to "apptools".
- **Fix:**
  - Move the colour-picking logic into `AppActions` as `pickAppearance(QWidget*, Document&, bodyIds)`. It opens `QColorDialog` once and pushes one `MacroCommand` of `makeSetBodyColor` commands.
  - Register `app.appearance`: name "Appearance", shortcut "A", aliases {"APPEARANCE"} (not "A", which is the sketch Arc alias, `CreateTools.cpp:1471`), tab SOLID, group MODIFY, order after Physical Material. Its target is the preselected bodies (components map to their bodies, faces to the owning body). With nothing selected it shows "Select bodies or components, then press A". Disable it in sketch mode.
  - `BrowserTree` calls the shared helper.
  - Override `BrowserTree::keyboardSearch(const QString&)` as a no-op; Fusion's browser has no type-ahead. Check whether screenshot 150 is really an inline editor: edit triggers are `NoEditTriggers` (`:61`), so it is probably only the type-ahead selection.
- **Possible effects:**
  - In sketch mode A must not open the colour dialog. Because the Shortcut loop (`MainWindow.cpp:1770`) stops at the first tool with that shortcut, disabling the tool in sketch mode is enough.
  - `BrowserTree.cpp` is shared with G1 (root label only). Keep the edit to `keyboardSearch` and the helper call.
  - `QColorDialog::getColor` is modal: do not reach it from scripts (no-arg run only), or accept `APPEARANCE #rrggbb` for scripts and tests.

## APP-06 (low): Enter in an empty cmd box repeats the last command and cancels the pattern prompt
- **Root cause:** `CommandLine::submit` (`src/app/CommandLine.cpp:96-105`) calls `ToolManager::runCommandLine("")`, which runs `repeatLast()` (`src/core/Tool.cpp:287`) even while a tool is active. Starting the repeated tool cancels the active one.
- **Fix:** keep core unchanged, because scripts rely on the current `runCommandLine` semantics. In `CommandLine::submit`, if the text is empty and `manager_->isActive()`, emit a new `emptyEnter()` signal and return. `MainWindow` connects it to `handleKeyPress(Qt::Key_Return, 0, "\r", false, viewer_)`, the same path as Enter on the canvas: tool `keyPress` first, then `AcceptOrRepeat`, which respects `acceptEnabled_` and idle tools. With no active tool, keep `repeatLast`.
- **Possible effects:**
  - It needs a one-line `connect` in `MainWindow.cpp` (G1).
  - The completer popup path (`:139`) only submits non-empty text, so it is unaffected.
  - G4 SK-08 (typed entry in sketch prompts) uses the same Enter path, so agree on it with G4.

## APP-07 (low): ':' focuses the command box but also inserts a colon
- **Root cause (not reproduced yet):** `routeKey` returns `FocusCommandLine` (`src/app/ShortcutRouter.cpp:96`), `handleKeyPress` moves focus and returns true (`MainWindow.cpp:1766`). The text still arrives in the new focus widget, probably through a second delivery (input method commit or a duplicate key event under XWayland or xdotool) after the focus change.
- **Fix:** reproduce on display :33 first. Defensive fix inside `CommandLine`:
  - Add `focusForTyping()`, which `MainWindow::focusCommandLine` calls. It sets `swallowColon_ = true`.
  - In `eventFilter`, a `KeyPress` or `InputMethod` event whose text is ":" while the flag is set is dropped. Any other key, or a 200 ms single-shot timer, resets the flag.
  - Also strip leading ':' in `submit()` as a safety net.
- **Possible effects:**
  - Typing a real ':' later in the box still works, because the flag is one-shot.
  - Keep the existing router test for Colon (`test_app_logic.cpp:99`).

## APP-08 (low): Ctrl+Z in the cmd box recalls old text instead of undoing the model
- **Root cause:** `isStandardEditKey` (`ShortcutRouter.cpp:32`) leaves Ctrl+Z to text fields. `CommandLine::submit` uses `edit_->clear()` (`:98`), which is undoable in `QLineEdit`, so Ctrl+Z brings the last command text back.
- **Fix:**
  - Use `edit_->setText(QString())`, which resets the `QLineEdit` undo history, in `submit` and in the Escape handler.
  - In `CommandLine::eventFilter`: for Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z, when `!edit_->isUndoAvailable()` (or redo for the redo keys), run `manager_->run("app.undo")` or `"app.redo"` and consume the key. Otherwise let the line edit undo the user's own typing.
- **Possible effects:**
  - Other text fields keep their standard behaviour; the change is local to `CommandLine`.
  - `app.undo` while a tool is active: check that it is enabled the same way as from the canvas.

  - UNITS is not `keepsActiveTool`, so it cancels the active command; that is intended.

## APP-10 (low): S command search is noisy and ranks disabled commands first
- **Root cause:**
  - `ToolRegistry::search` (`src/core/Tool.cpp:138-157`) accepts subsequence matches on names and also on tooltips. A tooltip match scores 100 minus gaps minus length, which is often still at least 0, so "appear" matches "Search all commands". `fuzzyScore` subsequence (`:42-50`) has no limit on gaps.
  - `searchCommandIds` (`src/app/CommandSearch.cpp:23`) keeps registry order regardless of the enabled state; `updateResults` only greys disabled items (`:117`).
  - Tools from other workspaces (Drawing "Add Revision") are also listed.
- **Fix:**
  - Tooltip matching: substring only, at a word start, and only for queries of 3 characters or more.
  - Subsequence matching: only on name and aliases, and only when the gaps are at most the query length, or when every matched character starts a word (acronym).
  - In `searchCommandIds`, add an optional `std::function<bool(ITool*)> enabled` and a current-workspace hint. Stable-partition: enabled tools of the current workspace first, then the other enabled tools, then disabled ones.
- **Possible effects:**
  - `test_tool.cpp:75-81` expects "ex" and "ln" (subsequence of line) to match. Both stay within the gap rule.
  - `test_app_logic.cpp:293-298` calls `searchCommandIds` without a context, so the new parameter must default to "no reordering".
  - `Tool.cpp` is core and not owned by another group.

## APP-11 (low): Interference dialog truncates the Volume column and does not show the intersection
- **Root cause:**
  - `src/assembly/tools/InterferenceTool.cpp:139-141`: three columns, only the last stretches, the vertical header is shown, and the panel is narrow, so "Volume" scrolls horizontally (screenshot 117).
  - The red common-volume previews (`:95-97`) are drawn with `PreviewStyle::cut()` without `onTop`. They lie inside both opaque bodies, which `highlightRow` (`:124`) also highlights, so they are hidden.
- **Fix:**
  - Table: hide the vertical header; columns 0 and 1 `Stretch` with eliding, column 2 `ResizeToContents`; format the volume with fewer decimals and a unit in the header ("mm³").
  - Preview: set `red.onTop = true` (or draw the edges `onTop` and the faces shaded). On row select, show only that pair's preview, brighter, and highlight the bodies with the edges-only highlight instead of the solid fill.
- **Possible effects:**
  - Previews are cleared by `finishActive`, so nothing is left behind.
  - Measure or other tools that use `PreviewStyle::cut()` are unaffected, because the style is copied locally.
  - The `onTop` shaded rendering path in the viewer: check that it draws filled shapes, not only glyphs (G3 owns `ViewerWidget`).

## APP-12 (low): the Sketch Palette overlaps the ViewCube
- **Root cause:**
  - The palette docks at a fixed `kTop = 150` (`src/app/SketchPalette.cpp:27`), and `CommandDialog` does the same (`kDockTop`, `src/app/CommandDialog.cpp:29`).
  - The ViewCube centre is at 115 px divided by dpr (`ViewerWidget.cpp:147,1555`), with an 80 px cube plus face-step arrows. In front view its bottom reaches about 190 px or more, so the palette title covers it (advanced-sketch/173.png).
- **Fix:**
  - Add a public `QRect ViewerWidget::viewCubeRect() const` (the union of `cubeControls()` and the cube box, in logical px).
  - `SketchPalette::reposition`, the resize path (`:152`) and `CommandDialog::dockTop` use `max(kTop, cubeRect.bottom() + 8)`.
  - In `clampToParent`, if the viewport is too short, collapse the options instead of pushing the palette up over the cube.
- **Possible effects:**
  - `ViewerWidget.cpp` belongs to G3. This is an accessor only, so coordinate with them.
  - Sharing the dock top in `CommandDialog` moves every command dialog down by about 50 px, which reduces the room for tall dialogs. `relayout` already caps the body height and scrolls.
  - The reported clipping below about 1400 px was the harness display, so there is no responsive-layout work.
